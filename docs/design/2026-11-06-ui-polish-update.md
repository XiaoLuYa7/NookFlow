# NookFlow 界面与动画精修更新设计文档

日期：2026-11-06
版本：设计稿 v1
方向：保留现有布局，精修视觉、反馈与动画
状态：供设计评审与后续实施；本文列出的更新尚未实现。

## 1. 范围与设计依据

用户已确定保留当前布局。保留设置侧边栏及页面顺序、首页预览位置、左右侧信息选择区、模块横向卡片、灵动岛各功能页和文件工具栏布局。保留现有用户设置、模块顺序和窗口定位机制。

本次依据为聊天中的首页与文件页截图，以及当前工作区的设计令牌、设置组件、音乐设置和窗口动画源码。没有完成全页面实时走查与逐帧录屏；文中的视觉判断仅针对已有截图，动画数值为待验证的设计起点，不代表已测出的性能问题。

设计参考 Apple Design 技能中的即时反馈、可打断动画、空间一致性与无障碍原则；技能中的网页实现方式不直接移植，使用项目既有 SwiftUI／AppKit 实现。

不包含：重新设计导航、新增付费方案、更改播放器读取权限默认值、调整音乐来源优先级、文件操作语义或窗口核心几何算法。

## 2. 本轮目标

1. 同类控件保持一致的文字、间距、圆角与状态。
2. 保留现有信息密度，降低重复装饰的视觉重量。
3. 让开启、未检测到内容、加载失败、不可用具有明确区别。
4. 动画能被连续操作打断，停止操作后不持续消耗刷新资源。
5. 精修不改变用户已经熟悉的入口和操作路径。

## 3. 视觉规范

所有尺寸为 macOS 逻辑点 pt；优先复用 AppDesignSystem，避免页面独立添加近似常量。

| 项目 | 精修方案 | 约束 |
| --- | --- | --- |
| 页面主标题 | 现有 29pt 试调为 26pt semibold | 只改变标题视觉重量，不调整页面区域位置 |
| 页面副标题 | 保留 14pt regular | 优先一句说明；窄窗口允许换行 |
| 分组标题 | 16pt semibold | 与组内首行保持稳定间距 |
| 设置行标题 | 保留 14pt，普通行试用 medium | 强调通过状态表达，避免全部加粗 |
| 辅助说明 | 12pt regular／medium | 状态与错误不能只靠浅灰色区分 |
| 工具栏文字 | 13pt medium／semibold | 图标视觉宽度稳定，名称排序固定显示 Aa |
| 间距 | 继续使用 4／8／12／16／20／24／32 档位 | 保留页面横向 32pt、分组 24pt 基线 |
| 卡片内边距 | 16pt 为基线，紧凑卡片可用 12pt | 同一排标题和操作基线对齐 |
| 圆角 | 控件 10pt、卡片 12–13pt，沿用已有值 | 灵动岛外壳圆角与刘海适配不在本轮改变 |
| 强调色 | 保留现有蓝色 | 用于选中、主要操作、焦点，不覆盖所有装饰 |
| 阴影与描边 | 同层卡片统一，阴影轻于悬浮弹层 | 不叠加明显阴影、渐变、粗描边 |

设置页延续现有浅色视觉。当前 AppColor 多处使用固定浅色值，本轮不将其声明为完整深色主题；如果应用已有强制浅色策略，应保留。完整随系统深浅切换列为后续独立事项，避免只替换背景导致文字不可读。灵动岛延续黑色界面。

## 4. 设置首页精修

### 4.1 侧边栏

- 保留当前宽度、分组和收起入口。
- 选中项使用现有蓝色浅底；选中标记、文字、图标保持一致基线，避免同一项同时出现强描边与重阴影。
- 悬停只增强背景，按下立即降低背景亮度或强调填充，不缩放整行。
- 收起侧边栏后保留工具提示和辅助功能名称；键盘焦点可见。

### 4.2 标题与预览

- 保留标题及预览先后位置；降低标题装饰块与阴影的重量。
- “默认／展开”保持原切换位置，选中态清晰，不新增第二套切换控件。
- 预览仅在相关设置改变时更新；不为装饰持续模拟网速、CPU 或音乐波形。
- 演示数值需要在预览区用一处轻量说明标明“效果预览”，避免被误认为设备实时数据。

### 4.3 左右侧状态

- 保留左右两列和现有候选项顺序。
- 候选项统一胶囊展示尺寸、名称基线、上下留白。
- 选中项使用一层蓝色细描边或背景，并带勾选语义；悬停和选中不能使用完全相同效果。
- “无”仍可选择，视觉上不能像被禁用的按钮。
- 只更新受影响的预览侧，不对整个候选区执行缩放动画。

### 4.4 小组件卡片

- 保留横向卡片和用户排列顺序。
- 卡片标题、说明、设置入口和开关分别对齐；说明最多两行。
- 各模块保留现有识别色，但减轻大面积底色；功能状态通过开关与说明表达。
- Pro 标记统一尺寸和位置；不能挤压卡片标题或覆盖操作。
- 若实际支持拖动重排，悬停时出现轻量拖动提示；普通设置点击不能误启动拖拽。

## 5. 音乐设置精修

保留“支持应用 → 显示内容 → 应用访问”的现有结构和全部开关位置。

### 5.1 文案与层级

- 将“按需开启微光乐境可访问的应用来源”改为“选择允许 NookFlow 读取播放信息的应用”，统一品牌。
- 支持应用区表示兼容范围，不使用容易被理解为已经连接的装饰状态。
- 显示位置的三个选项采用一致尺寸与选中样式；保留当前单选／多选语义。
- 应用访问行保留应用名称、说明与右侧开关。

### 5.2 来源状态（需要补充逻辑，单独实施）

在原行说明区域显示短状态，不新增设置分区，不改变授权行为：

| 状态 | 显示文案 | 判定与动作 |
| --- | --- | --- |
| 用户关闭 | 未开启读取 | 仅根据现有开关判断 |
| 已开启但没有有效信息 | 已开启 · 暂未检测到播放信息 | 不直接推断为播放器未启动或系统故障 |
| 有有效播放信息 | 正在播放／已暂停 | 使用已有快照，并识别实际所属应用 |
| 已确认读取失败 | 读取失败 | 仅在捕获具体错误时显示原因及可执行操作 |

QQ／网易云共用系统当前媒体来源，不能因为只拿到其中一个就显示另一个“连接失败”。状态更新复用现有事件，不增加轮询。音乐来源统一选择是独立逻辑修复，不夹带在视觉更新中。

## 6. 其他设置页

- 待办、应用、指令、通知、通用、关于及许可页面保留当前分组和入口。
- 应用统一设置行、开关、分隔线与错误提示组件；同类操作的位置保持一致。
- 长说明允许增加行高，右侧开关不能被挤出窗口。
- 不可用选项显示原因；付费限制、缺少系统权限与功能关闭使用不同说明。
- 错误保留在相关操作附近，可提供重试；成功提示不持续占用大块空间。
- 更新、授权等异步操作使用原位进度状态，并防止重复提交。具体授权／付费行为本轮不变。

## 7. 灵动岛与文件页

### 7.1 灵动岛卡片

- 保留卡片宽度体系与整体排列；统一标题、辅助信息、底部操作的对齐关系。
- 歌曲名称和歌手较长时采用截断和完整内容提示，避免挤压播放控制。
- 进度数字使用等宽数字，减少时间变化时的横向抖动。
- 悬停只改变对应控件或卡片，不使整组卡片升降。
- 图标按钮补充明确名称与工具提示，例如“下一首”“打开音乐应用”。

### 7.2 文件工具栏与空状态

- 保留“路径 → 搜索 → 分类 → 排序”的顺序。
- 名称排序使用 Aa，其他排序保留符号；整枚按钮的可访问名称为“排序：名称”等完整含义。
- 路径过长时压缩中间段，保留末级目录与根入口，悬停可看完整路径；不给搜索框无限压缩空间。
- 空目录在内容区显示轻量图标、“这里还没有文件”和“将文件拖入灵动岛，即可添加到此处”的说明；实施前核对实际导入目标，若始终导入根目录则明确写“添加到 FileData”。
- 搜索无结果使用“未找到匹配文件”，附清除搜索操作；读取失败显示错误原因，不能沿用空目录文案。
- 隔空投送区域保留原位置与功能，拖入有效对象才突出边框和提示。

### 7.3 拖拽状态

| 阶段 | 反馈 |
| --- | --- |
| 开始拖动 | 显示被拖动文件的真实缩略图／图标与名称，保留抓取偏移 |
| 排序候选 | 用占位和局部让位表示插入位置 |
| 文件夹候选 | 文件夹轮廓高亮，提示“移入…”；与排序占位区分 |
| 不可放置 | 禁止标识及简短原因；不能只依赖红色 |
| 提交 | 等文件操作确认成功后更新完成状态 |
| 失败 | 恢复合理展示位置并显示具体错误；不播放成功反馈 |

## 8. 动画规范与候选参数

以下为评审起点，不是直接批量替换所有动画的指令。现有打开动画令牌约 0.69–0.87 秒，页面切换约 0.40 秒；这些是代码参数，不等于实测交互延迟。先录制基线，再决定哪些值需要缩短。

| 场景 | 候选方案 | 减少动态效果 |
| --- | --- | --- |
| 按钮悬停 | 100–140ms 颜色／透明度 | 即时或短淡变 |
| 按下反馈 | 按下即时反馈，释放恢复 80–120ms | 保留颜色反馈，不缩放 |
| 设置页面切换 | 140–180ms 淡变，页面保持原位 | 即时或不超过 100ms 淡变 |
| 卡片启用／禁用 | 140–180ms 状态变化 | 即时状态变化 |
| 灵动岛展开 | 保留当前路径；试验总时长 0.50–0.65 秒，减小末尾反复回弹 | 使用已有减少动态效果路径，取消过冲 |
| 灵动岛收起 | 以现有实现为基线，试验 0.25–0.40 秒 | 短淡变与必要尺寸变化 |
| 内容显隐 | 100–160ms，不给文字整体缩放 | 80–100ms 淡变 |
| 拖拽让位 | 120–180ms，仅邻近项目 | 即时换位／位置标识 |

实施原则：

1. 新交互中断旧动画，从当前呈现值继续；不先跳到上一目标再反向。
2. 内部文字保持自然尺寸，外壳扩张通过裁切和透明度衔接。
3. 不通过增加等待时间解决布局闪烁；先排查状态和测量依赖。
4. 页面切换不新增整页横向飞入；滚动位置、搜索内容和焦点遵循现有语义。
5. 弹簧 response 是响应参数，不将其误当固定持续时间。
6. 不新增高频 Timer、常驻波动或重复无限动画；动画结束后不保留额外刷新任务。
7. 多屏幕、刘海、缩放适配以现有几何模型为准，不使用固定屏幕坐标。

## 10. 验收清单

### 视觉与操作

- [ ] 保存更新前后相同窗口尺寸的首页、音乐设置、文件页截图。
- [ ] 侧边栏、模块顺序、设置分组、文件工具栏位置符合原布局。
- [ ] 窄窗口、长中文名称、英文名称和多行说明不遮挡主要操作。
- [ ] 所有按钮具备悬停、按下、键盘焦点和不可用状态。
- [ ] Aa 在中文环境保持 Aa，屏幕阅读名称仍为“排序：名称”。
- [ ] 空目录、搜索无结果、读取失败三种状态能明确区分。
- [ ] 音乐开关关闭、开启无信息、播放、暂停均显示准确。

### 动画与无障碍

- [ ] 连续执行展开—收起—展开 10 次，无跳位、残留内容或被锁住的操作。
- [ ] 连续切换首页、应用、文件页，焦点与点击区域对应当前可见页面。
- [ ] 拖拽快速越过多个目标，只有当前有效目标显示接收状态。
- [ ] 减少动态效果、减少透明度、增强对比度分别检查。
- [ ] 内置刘海屏与外接屏，以及不同缩放设置下无位置偏移。

### 性能与工程

- [ ] 在同一机器、同一数据下，各记录更新前后静置 60 秒、展开 60 秒、反复操作三组 CPU／内存和活动任务数。
- [ ] 隐藏页面和停用功能后，本轮新增任务归零；没有新增周期性唤醒。
- [ ] 动画结束后资源占用回到该场景基线；持续增长必须定位原因。
- [ ] 编译通过；状态逻辑变更添加针对性测试，纯样式不添加复述实现的测试。
- [ ] 只有完成截图、操作与性能验证后才标记阶段已验收。
